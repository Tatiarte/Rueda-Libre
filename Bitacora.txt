1. Prueba de solicitud HTTP con Live Server
URL http://127.0.0.1:5500/Rueda-Libre/index.html significa lo siguiente:
    - Protocolo HTTP: Es el protocolo que permite la comunicación entre el navegador y el servidor web.
    - Host: 127.0.0.1 - Es una dirección IP que apunta al propio computador, donde se está ejecutando Live Server.
    - Puerto: 5500 - la entrada por la que el Live Server me atiende. Es decir es el puerto en el que Live Server escucha las solicitudes del navegador.
    - Ruta: /Rueda-Libre/index.html: al igual que la teoria del moodle, la ruta nos indica el recurso del servidor, es decir que usa mi file del local
    - Método HTTP: GET - porque de momento solo estamos obteniendo información no enviando datos para procesarlos
    - Código de estado observado inicialmente: 304 Not Modified - Esto ocurrio porque ya había abierto la página antes y el navegador tenia una copia de 
    recursos en caché.
    - Código de estado después de desactivar el caché: 200 ok - en Network aparecia una casilla para señalar que deshabilitara el caché y así al recargar
    pidio el contenido solicitado como normalmente

MINIRETO 1
Creé la carpeta nocturna/ y dentro el archivo prototipo.html, con la estructura base de HTML y el script del Play CDN de Tailwind (<script src="https://cdn.tailwindcss.com"></script>). Con él prototipé la sección principal de la campaña “Rueda Nocturna”: la etiqueta “Nuevo · Jueves a sábado”, el título principal (el único h1 de la página), el subtítulo, los dos datos destacados (“3 rutas” y “Desde $55.000”) y el enlace “Inscríbete”.

Cómo le di estilo

Usé solo utilidades de Tailwind, sin <style>, sin style="" y sin clases de Bootstrap. Usé las cuatro familias que pedía el reto:

Espaciado: space-y-6, px-6, py-20, mx-auto, gap-10.
Tamaños: max-w-3xl, max-w-xl, w-full.
Colores: bg-slate-950, bg-amber-400, text-slate-300, text-amber-400.
Tipografía: text-5xl, font-bold, leading-none, tracking-tight, uppercase.

Cómo construí el botón “Inscríbete”

Es un enlace (<a>) con apariencia de botón, armado combinando utilidades pequeñas: inline-block bg-amber-400 px-8 py-3 text-center font-bold text-slate-950. Cada clase hace una sola cosa: el fondo, el espaciado interno, el peso y el color del texto. Así controlo cada detalle del botón directamente en el HTML, sin escribir CSS aparte.

Diferencia clave entre un framework de componentes y uno utility-first

Un framework de componentes, como Bootstrap, entrega piezas ya diseñadas (por ejemplo .btn o .card): son rápidas de usar, pero el resultado se parece al de otros sitios y personalizarlas implica sobrescribir estilos. Uno utility-first, como Tailwind, entrega solo piezas pequeñas (colores, espacios, tipografía) y el diseño se arma combinándolas en el HTML. Se escribe más en el HTML, pero el resultado es propio y no depende de un diseño predefinido.


MINIRETO 2
Qué busqué en output.css

Después de ejecutar la CLI de Tailwind con --watch, abrí src/output.css y busqué dos clases. Busqué bg-amber-400, que sí uso en los botones y en la etiqueta de la campaña, y apareció con su regla de CSS. Busqué bg-pink-500, que no uso en ninguna parte del proyecto, y no apareció.
Por qué ocurre

La CLI de Tailwind no copia todas sus clases al archivo final. Primero escanea mis archivos (como index.html), detecta qué clases escribí y genera solo el CSS de esas. Como bg-pink-500 no está escrita en ningún archivo del proyecto, Tailwind no la incluye. Esto mantiene output.css pequeño y sin estilos que nadie usa. Si agrego una clase nueva al HTML y guardo, el modo --watch regenera el archivo y la clase aparece sola.
Diferencia con el Play CDN

En el prototipo, el Play CDN descargaba y compilaba Tailwind en el navegador cada vez que se abría la página. Con la CLI el CSS se genera una sola vez, antes de publicar, y la página solo carga un archivo ya listo. Por eso output.css se sube a GitHub, porque GitHub Pages no ejecuta la CLI.
